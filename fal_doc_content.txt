

AURA AI — NEW AI HAIRSTYLE TRY-ON IMPLEMENTATION
Fal.ai Hair Change • React • ASP.NET Core • MediaPipe
1. Objective
Replace the failing Gemini image-generation layer with a hairstyle-specific image-to-image service. The target is a photorealistic hairstyle visualization that keeps the same person, face, pose, clothing and background as much as possible while changing the hair.
2. Recommended AI Provider
Use fal.ai Hair Change as the first production integration. The current fal.ai documentation provides two relevant endpoints: fal-ai/image-editing/hair-change for free-form hairstyle prompts, and fal-ai/image-apps-v2/hair-change for structured hairstyle and hair-color choices. Both are image-to-image hair-change APIs.
Primary endpoint: fal-ai/image-editing/hair-change
Alternative structured endpoint: fal-ai/image-apps-v2/hair-change

5. Critical Security Rule
Never expose FAL_KEY in React or any VITE_* variable. fal.ai's current documentation explicitly recommends a server-side proxy for browser applications. Keep the key only in ASP.NET Core environment configuration.

9. User Flow
1. Open Aura AI.
2. Take a photo or upload one.
3. Run face-quality checks locally.
4. Choose a hairstyle.
5. Optionally choose hair color.
6. Send the photo and hairstyle ID to ASP.NET Core.
7. Backend uploads/uses the source image URL.
8. Backend submits the job to fal.ai.
9. Store the provider request ID.
10. Poll the job or process its webhook result.
11. Store the generated image.
12. Return the result to React.
13. Show before/after and allow retry.
10. AI Endpoints
Free-form Hair Change:
{  "image_url": "https://storage.example/source.jpg",  "prompt": "low fade with textured crop, natural black hair, realistic individual strands and natural hairline",  "output_format": "jpeg",  "aspect_ratio": "3:4"}
Structured Hair Change:
{  "image_url": "https://storage.example/source.jpg",  "target_hairstyle": "side_part",  "hair_color": "natural",  "aspect_ratio": "3:4"}
The current structured endpoint documents hairstyle choices such as short_hair, medium_long_hair, long_hair, curly_hair, wavy_hair, bob_cut, pixie_cut, braids, buzz_cut, mohawk, bangs, side_part and middle_part, plus multiple hair-color choices.
11. Realistic Hair Prompt
Change ONLY the hairstyle.Selected hairstyle:{HAIRSTYLE_DESCRIPTION}Preserve the same person's identity and facial geometry.Do not change eyes, eyebrows, nose, lips, jaw, chin, ears, skin tone or apparent age.Do not change clothing, body, pose, camera angle or background.Create photorealistic human hair:- natural hairline- realistic density- individual strands- believable scalp transition- physically believable volume- realistic fade/blending- lighting and shadows matching the source photo- texture appropriate to the selected hairstyleThe final image must look like a real photograph of the same person after receiving the haircut.Avoid wigs, pasted overlays, plastic hair, CGI appearance, illustrations or distorted facial features.

17. Face Validation
Exactly one face detected.
Face large enough in the image.
Eyes/major landmarks visible.
Head rotation within acceptable range for MVP.
Image not excessively blurred.
Adequate lighting.
Prefer full head/hair region visible.
MediaPipe is for local guidance and validation. It is not the hair-generation model.
18. Quality Rules for Realistic Results
Use a clear front or 3/4 portrait.
Keep the full head inside the capture frame.
Use hairstyle-specific technical descriptions.
Preserve identity and facial geometry.
Match the original lighting and camera perspective.
Use realistic hair density and hairline language.
Allow regeneration because generative output varies.
Maintain a fixed test-photo set for regression testing.

20. Privacy & Security
Keep FAL_KEY server-side.
Use HTTPS in production.
Validate MIME type and maximum upload size.
Use private/signed image URLs when appropriate.
Delete temporary images according to your privacy policy.
Do not use user photos for training without explicit permission.
